## 0. 摘要

**目标**：在单块 RoboMaster C 型开发板（STM32F407IG，即当前 `CHASSIS_BOARD` 目标板）上，接入 DT7 遥控器（DBUS 协议，USART3），直接驱动舵轮底盘（4×M3508 驱动 + 4×GM6020 舵向）完成平移/小陀螺运动，作为双板联调前的单板开发验证阶段。

**核心结论**：

1. **遥控器模块本身完好可用**，USART3 的 DBUS 硬件参数（100000bps / Even / 9 位字长）已在 CubeMX 中配置完毕，`RemoteControlInit(&huart3)` 一行即可接入。
2. **当前指令链路对单板场景完全断开**：`robot_cmd.c` 始终参与编译（CMakeLists GLOB_RECURSE 无条件收录 application/*.c），但 `CHASSIS_BOARD` 下 `RobotCMDInit()`/`RobotCMDTask()` 的调用点被 robot.c 的 `#if` 排除（:32-36,:50-54），函数无调用者；底盘指令唯一来源是云台板经 CANComm（can1 tx 0x311 / rx 0x312）。单板无云台板 → CANComm 恒判离线（约 1s 超时）→ 底盘恒 `CHASSIS_ZERO_FORCE`，**这是"必须新增指令来源"的根本原因**。（第 6 轮交叉验证勘误 E-1，2026-10-09）
3. **发现安全缺陷 RC-1**：`RemoteControlIsOnline()` 在全工程零调用。断连后 `RCLostCallback` 清零 rc 数据 → 开关值 0 → 所有 `switch_is_*` 判断不命中 → 指令冻结在最后值且**不触发急停**。本方案在新链路中必须内建离线保护。
4. **推荐方案 A**：保持 `CHASSIS_BOARD` 板型不变，新增 `CHASSIS_RC_DIRECT` 特性宏，在 `chassis.c` 内新增 RC bridge（约 60 行条件编译代码），不触碰 robot.c / robot_cmd.c / 云台侧任何文件。回退成本 = 注释一行宏定义。
5. **前置修复 4 项**（阶段 0）必须先行，其中 `bsp_usart.c` 的裸 `while(1)` 修复是遥控器注册链路（`USARTRegister`）的可靠性前提。
6. 分 **5 个阶段** 实施：阶段 0 前置修复 → 阶段 1 遥控器接入 → 阶段 2 台架空轮验证 → 阶段 3 落地安全调优 → 阶段 4 双板回归。

## 2. 现状诊断（指令链路断点分析）

### 2.1 现有指令链路（双板模式）

```
DT7遥控器 ──DBUS──> 云台板USART3 ──> 云台板robot_cmd.c(RemoteControlSet/EmergencyHandler)
                                        │ 200Hz 解算 Chassis_Ctrl_Cmd_s
                                        ▼
                                   CANComm(0x311/0x312)
                                        │
                                        ▼
                   底盘板 chassis.c ChassisTask() ──> 舵轮解算 ──> 8电机
```

关键编译边界（`application/robot.c`）：

- `RobotCMDInit()` / `RobotCMDTask()` 仅在 `ONE_BOARD || GIMBAL_BOARD` 下编译（robot.c:32-36, 50-54）
- `CHASSIS_BOARD` 下 `RobotTask()` 只调 `ChassisTask()`（robot.c:56-58）

**单板场景**：无云台板发帧 → `CANCommIsOnline()` 在 daemon 超时后恒 false（chassis.c:413）→ 每周期 memset + `CHASSIS_ZERO_FORCE` → 8 电机 `DJIMotorStop`。上电后最初约 1 秒 daemon 未超时，但收到的数据全 0，`chassis_mode=0` 恰好等于 `CHASSIS_ZERO_FORCE`，同样安全。**结论：现状是"安全但完全不可动"，需要新增指令来源。**

### 2.2 可复用的既有资产（调研确认）

### 2.3 安全缺陷 RC-1：遥控器离线保护全链路缺失（本方案必须修复）

**机理**（三个事实叠加）：

1. `RemoteControlIsOnline()` 全工程零调用（`grep -rn` application/ modules/ 无任何调用点）；
2. `EmergencyHandler()` 仅判断开关位置，注释自认"还需添加重要应用和模块离线的判断"（robot_cmd.c:500）；
3. 断连后 `RCLostCallback` 将 rc 数据 memset 清零 → `switch_left/switch_right = 0` → `switch_is_up/mid/down(0)` 全部为假 → `RemoteControlSet` 所有分支不命中 → **`chassis_cmd_send` 冻结在断连前最后值**，且不触发急停。

**后果**：断连 = 底盘保持最后指令持续运动，直到 CANComm 一侧被云台板喂狗超时（单板场景无此链条）。原双板链路中该缺陷被"云台板停发帧 → 底盘板 CANComm 1s 超时 → 零力"间接掩盖；单板直控后**没有任何兜底**，必须在 RC bridge 中作为第一优先级内建。

## 3. 指令链路设计

### 3.1 方案比选

| | 方案 A：`CHASSIS_RC_DIRECT` 特性宏（推荐） | 方案 B：切换 `ONE_BOARD` | 方案 C：CHASSIS_BOARD 下启用 robot_cmd.c |
|---|---|---|---|
| 思路 | 保持 `CHASSIS_BOARD`，chassis.c 内新增 RC bridge | robot_def.h 改单板宏 | robot.c 放开 RobotCMDInit 编译条件 |
| 云台/发射依赖 | 无 | `GimbalInit/ShootInit/RobotCMDInit` 全部编译，初始化不存在的云台电机/DM 电机/图传链路，CAN 上挂错误 ID 的电机实例，行为不可预期 | robot_cmd.c 依赖 vision/solvetrajectory/shoot/gimbal 一整串云台侧模块，牵连面最大 |
| 改动范围 | chassis.c + robot_def.h，约 60 行条件编译 | 1 行宏 + 大量不可控初始化路径 | robot.c + robot_cmd.c + 一串头文件依赖 |
| 回退成本 | 注释 1 行宏 + 重编译 | 1 行宏，但期间踩坑成本高 | 中等 |
| 双板回归 | 宏注释即回到原链路，零回归成本 | 同左 | 需再改回编译条件 |

**结论：采用方案 A。**

### 3.2 总体结构

```
DT7 ──DBUS──> USART3(DMA+IDLE) ──> RemoteControlRxCallback ──> rc_ctrl(±660摇杆/开关1|2|3)
                                        │ daemon 100ms喂狗,断连触发RCLostCallback
                                        ▼
                chassis.c: RCDirectSet()  ←── 新增,200Hz,与ChassisTask同频
                  ① RemoteControlIsOnline()==0 → 零力   (修复RC-1)
                  ② 左开关[上] → 零力(急停)
                  ③ 右开关: [上]ROTATE / [中]NO_FOLLOW / [下]降级NO_FOLLOW / default零力
                  ④ 右摇杆→vx/vy (死区+缩放), offset_angle=0
                                        ▼
                chassis_cmd_recv (Chassis_Ctrl_Cmd_s) ──> 既有 ChassisTask 主流程(不动)
                  ZERO_FORCE→8×DJIMotorStop+PIDReset / 模式switch / 舵轮解算 / SetRef
```

**新增 RCDirectSet()**（放在 ChassisTask 之前）：

```c
#ifdef CHASSIS_RC_DIRECT
/**
 * @brief 遥控器直控指令桥: 将DBUS数据映射为Chassis_Ctrl_Cmd_s
 * @note  安全优先级: ①断连零力 ②左开关急停 ③default兜底非法开关值
 *        与ChassisTask同频运行(200Hz),断连检测延迟=daemon 100ms+任务周期5ms
 */
static void RCDirectSet()
{
    // ① 离线保护(最高优先级,修复RC-1): 断连立即零力,不依赖开关位置
    // ② 左开关[上]=急停(语义沿用原EmergencyHandler)
    if (!RemoteControlIsOnline() || switch_is_up(rc_data[TEMP].rc.switch_left)) {
        memset(&chassis_cmd_recv, 0, sizeof(Chassis_Ctrl_Cmd_s));
        chassis_cmd_recv.chassis_mode = CHASSIS_ZERO_FORCE;
        return;
    }

    // ③ 模式映射(带default兜底: 离线清零后的switch=0及其他非法值全部落入零力)
    switch (rc_data[TEMP].rc.switch_right) {
    case RC_SW_UP: // [上] 小陀螺+全向平移(ChassisTask内强制wz=25)
        chassis_cmd_recv.chassis_mode = CHASSIS_ROTATE;
        break;
    case RC_SW_MID: // [中] 全向平移,不旋转
    case RC_SW_DOWN: // [下] 单板无云台编码器,FOLLOW_GIMBAL_YAW不可得,降级为NO_FOLLOW
        chassis_cmd_recv.chassis_mode = CHASSIS_NO_FOLLOW;
        break;
    default: // 非法开关值兜底(双保险,正常不会走到)
        memset(&chassis_cmd_recv, 0, sizeof(Chassis_Ctrl_Cmd_s));
        chassis_cmd_recv.chassis_mode = CHASSIS_ZERO_FORCE;
        return;
    }

    // ④ 右摇杆→底盘速度. rocker量纲±660,死区沿用CHASSIS_DEAD_BAND(10)
    float vx_in = (float)rc_data[TEMP].rc.rocker_r_;  // 右摇杆水平→x(右移为正)
    float vy_in = (float)rc_data[TEMP].rc.rocker_r1;  // 右摇杆竖直→y(前推为正)
    chassis_cmd_recv.vx = (ABS(vx_in) > CHASSIS_DEAD_BAND) ? vx_in * CHASSIS_RC_SPEED_SCALE : 0.0f;
    chassis_cmd_recv.vy = (ABS(vy_in) > CHASSIS_DEAD_BAND) ? vy_in * CHASSIS_RC_SPEED_SCALE : 0.0f;
    chassis_cmd_recv.offset_angle = 0.0f; // 单板无云台反馈,坐标系不旋转(摇杆向前=车体向前)
    chassis_cmd_recv.wz = 0;              // wz由ChassisTask模式分支设定(ROTATE=25)
}
#endif
```

### 3.4 设计决策说明

| 决策 | 理由 |
|---|---|
| 离线判断置于开关判断之前 | `RCLostCallback` 已把 rc 清零，开关值不可信；`RemoteControlIsOnline()` 是唯一可靠信号 |
| 右开关[下]降级为 NO_FOLLOW 而非零力 | ① `FOLLOW_GIMBAL_YAW` 需要云台 yaw 反馈算 offset_angle，单板不可得；② 降级保持右手不离位即可全向平移的操作连续性；③ 与原双板操作习惯（下=跟随）形成"单板调试语义"区分，文档化避免混淆 |
| default 分支必须显式零力 | 防御非法开关值（含 0）。注意原 ChassisTask 模式 switch 的 `default: break` 不处理 ZERO_FORCE 之外的悬挂值，本桥在入口处拦截，杜绝脏值进入下游 |
| offset_angle 恒 0 | 摇杆指令直接投到底盘坐标系（前推=车体前方），无云台系-底盘系旋转 |
| 缩放系数独立成宏且起步 8.0f | 原 NO_FOLLOW 系数 25.0f 对应满速（660×25=16500=CHASSIS_WHEEL_SPEED_MAX）；首次带电验证从约 1/3 满速起步，空载确认舵向/轮向后逐级上调 |
| wz 不在桥内设置 | 沿用 ChassisTask 既有模式机（ROTATE 强制 wz=25，NO_FOLLOW 强制 wz=0），单一职责 |
| 坐标系/方向疑义不在本阶段改 | 左手系解算（z 向下，y 前 x 右）与 `steering_dirt`、`motor_reverse_flag` 的方向匹配留待台架 F2-2 实测；方向反了只翻转缩放符号或 steering_dirt 元素，不动运动学 |

### 3.5 时序与延迟预算

| 环节 | 延迟 | 说明 |
|---|---|---|
| DBUS 帧间隔 | ≈14ms（71Hz） | 物理协议 |
| 摇杆→Chassis_Ctrl_Cmd_s | 0（同任务内直写） | RCDirectSet 与 ChassisTask 同频 200Hz |
| 断连→daemon 判离线 | 100ms（reload_count=10 @100Hz） | remote_control.c:121 |
| 判离线→电机零力 | ≤5ms（下一任务周期） | RCDirectSet ① |
| **断连→底盘零力最坏总延迟** | **≈105ms** | 可接受（业界常规 DBUS 失联保护量级） |
